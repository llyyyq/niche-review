# RAG 检索评测报告

## 1. 评测目的

验证本地生活 AI 助手的检索链路是否能在店铺名称、分类和商圈、优惠券、探店笔记、推荐及无结果问题中，稳定召回正确资料，并在缺少可靠资料时拒绝编造业务事实。

本报告以 [rag-cases.csv](rag-cases.csv) 中固定的 50 条案例为唯一数据来源。案例事实来自当前 MySQL 数据快照，检索使用实际运行的 Embedding 服务和 Qdrant，不使用模拟向量结果。

> 当前状态：50 条案例已于 `2026-07-23` 使用当前 MySQL、Embedding 服务和 Qdrant 实际执行完成。第 5 节为本次最终统计结果。

## 3. 案例组成与指标口径

| 场景 | 数量 | 验证方式 |
| --- | ---: | --- |
| 店铺名称精确查询 | 10 | 正确店铺是否进入 TopK |
| 分类 + 商圈查询 | 10 | 正确店铺是否进入 TopK |
| 预算约束查询 | 4 | 推荐结果是否满足预算和区域要求 |
| 优惠券查询 | 8 | 正确店铺是否进入 TopK |

| 无结果问题 | 7 | 空召回且最终回答明确拒答 |
| 模糊推荐问题 | 6 | 推荐店铺是否满足分类、商圈或预算要求 |
| 总计 | 50 | - |

其中 43 条具有明确的 `expected_shop_ids`，使用以下指标：

```text
Hit@1 = 第一名候选是否属于预期店铺集合
Hit@3 = Top3 候选中是否至少包含一家预期店铺
```

7 条无结果题没有“正确店铺 ID”，因此不纳入 Hit@1、Hit@3；它们单独验证“混合检索为空 + SSE 最终回答拒答且不虚构事实”。

## 4. 检索方法

每道题调用同一套 `IShopKnowledgeService` 两次：

1. 纯向量检索：`searchRelevantShops(question, false)`，仅使用 Qdrant TopK 向量召回。
2. 混合检索：`searchRelevantShops(question, true)`，在向量召回的基础上加入关键词候选、商圈/分类/预算等结构化约束、通用短语重合加权，再进行去重和 Top3 截断。

混合检索中的“短语重合加权”不依赖店铺 ID 或指定店名。例如用户问题与店名、商圈、地址、分类存在长度不少于 2 的连续公共片段时，候选获得额外排序分；这用于提升“火锅”等业务词与店名片段的匹配能力。

当问题看起来在询问一个明确店铺的业务事实，但系统没有识别到对应店铺时，混合检索返回空结果，聊天层直接返回无证据提示，不把无关店铺交给模型生成。

## 5. 50 条案例的最终结果

本次 50 条案例中，43 条具有明确预期店铺 ID，7 条为无结果题。两种检索方式均使用相同的 Top3 截断和相同的评测口径。

| 指标 | 纯向量检索 | 混合检索 | 差异 |
| --- | ---: | ---: | ---: |
| Hit@1 | 38 / 43 = 88.37% | 42 / 43 = 97.67% | +9.30 个百分点 |
| Hit@3 | 40 / 43 = 93.02% | 43 / 43 = 100.00% | +6.98 个百分点 |
| 无结果空召回 | 不适用 | 7 / 7 = 100.00% | - |
| 无结果正确拒答 | 不适用 | 7 / 7 = 100.00% | - |

无结果题的“正确拒答”由两部分共同验证：混合检索均返回空结果；聊天层对空结果的业务事实问题进入 `directResponse` 分支，直接说明当前资料未找到匹配信息，不再将无关店铺交给模型生成。典型的不存在店铺问题已完成前端 SSE 人工验证。

## 6. 当前边界

本次 `100% Hit@3` 仅说明在这 43 条固定、与当前数据快照一致的可命中题中，正确店铺至少进入了前三名；它不是生产环境的通用准确率承诺。混合检索的唯一 Hit@1 未命中是“运河上街的寿司店有哪些？”，正确店铺 8 排在第二名，说明当前排序仍有优化空间。

当前评测只衡量“正确候选是否召回”，不衡量 Top3 的全部候选是否都满足类别、预算和商圈条件。后续若要继续优化，可新增 Precision@3、类别纯度和答案事实正确率指标；本项目当前不把这些未验证能力写成既有结论。

## 7. 复现方式

1. 确认 MySQL、Qdrant、Embedding 服务均可用。
2. 在 IntelliJ 的 Environment variables 中临时添加：

```text
AI_EVALUATION_ENABLED=true
```

3. 启动应用，等待日志：

```text
RAG evaluation completed, scoredCases=43, ...
```

4. 查看 `rag-cases.csv` 中的 `vector_top3`、`hybrid_top3` 和四个 Hit 列。
5. 移除 `AI_EVALUATION_ENABLED`，再正常启动项目。

评测运行器只覆盖 CSV 中的检索结果列，不会修改 MySQL、Redis、Qdrant、会话数据或聊天记录。
