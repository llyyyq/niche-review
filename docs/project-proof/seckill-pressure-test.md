# 秒杀压测记录

## 测试目标

验证秒杀链路在大量不同用户并发请求时，不出现超卖、重复下单，并核对 Redis 预扣库存与 MySQL 最终库存的一致性。

## 测试环境与配置

- 压测工具：Apache JMeter
- 目标接口：`POST /voucher-order/seckill/23`
- 优惠券：`voucher_id = 23`
- 初始库存：100
- 压测用户：10,000 个不同登录 Token，通过 `tokens.csv` 轮询提供
- 线程数：10,000
- 循环次数：1
- Ramp-Up：30 秒
- 请求直接发送到后端 `http://localhost:8081`，不经过 Nginx

## JMeter 原始结果

| 指标 | 结果 |
| --- | ---: |
| 请求样本数 | 10,000 |
| 吞吐量 | 333.2 req/s |
| 平均响应时间 | 13 ms |
| 中位数 | 8 ms |
| P90 | 15 ms |
| P95 | 24 ms |
| P99 | 198 ms |
| 最大响应时间 | 438 ms |
| JMeter 异常率 | 99.00% |

### 异常率口径

这里的 `99.00%` 不是后端系统异常率。压测券只有 100 张，10,000 个不同用户中只有 100 个请求能够抢到库存；其余约 9,900 个请求收到“库存不足”等预期业务拒绝结果，并被 JMeter 的 JSON 断言记为失败。

本轮压测期间后端未观察到 RocketMQ 发送超时、消费异常或未处理的服务端异常日志。因此结论应表述为：**业务售罄请求约占 99%，系统异常观察结果为 0。**

## 最终一致性核对

压测后执行 `seckill-verify.sql` 中的核对语句，实际结果如下：

| 校验项 | 实际结果 | 预期 |
| --- | ---: | ---: |
| MySQL 订单数 | 100 | 100 |
| MySQL 下单唯一用户数 | 100 | 100 |
| MySQL 秒杀库存 | 0 | 0 |
| Redis `seckill:stock:23` | `"0"` | `"0"` |
| Redis `SCARD seckill:order:23` | 100 | 100 |

结论：在该轮 10,000 名不同用户、30 秒 Ramp-Up 的压测下，订单数和唯一用户数均为 100，Redis 与 MySQL 库存均归零，未发现超卖或重复下单。

## 简历可用表述

使用 JMeter 模拟 10,000 名不同用户在 30 秒内抢购 100 张优惠券，压入速率约 333 req/s；通过 MySQL 订单数/唯一用户数、MySQL 库存及 Redis 预扣库存核对，验证无超卖、无重复下单，并将售罄等业务拒绝与系统异常分开统计。
